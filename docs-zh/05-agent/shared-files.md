# 共享文件与下载

Agent 可以接受任意文件上传，这与图像/音频聊天附件相互独立。上传的文件和生成的输出对 Agent 而言是本地路径，对 Web/App 用户而言则可供下载。

## 设备存储与服务

在 userdata 迁移完成后，`share.mount` 会把 `/userdata/share` bind mount 到 `/share`。它使用现有的持久化 userdata 文件系统，不会对设备重新分区或格式化。文件在 Agent 重启和 rootfs 槽位更新后依然保留。它们会占用 userdata 容量，且清除聊天历史时不会被删除。请通过 `DELETE /api/files` 删除它们；参见[删除文件](#删除文件)。

Agent 在其现有的 HTTP 端口（8080）上提供 `POST /api/files`、`GET /api/files`、`DELETE /api/files` 和 `/share/`。设备服务还会设置 `AICO_SHARE_ADDR=0.0.0.0:8000`，启动一个只暴露这些文件路由的监听器。两个监听器都遵循设备的 LAN 访问开关和设备密码：来自其他网络的访问需要启用 LAN 访问；设置了设备密码时，除开发板自身外的所有客户端都需要会话。例如：

```text
Agent path: /share/report.pdf
Download:  http://192.168.42.1:8000/share/report.pdf
Web/App:   http://192.168.42.1:8080/share/report.pdf
```

两个监听器共享同一份存储。`AICO_SHARE_DIR` 可在桌面开发时覆盖绝对存储目录；在设备服务之外，`AICO_SHARE_ADDR` 是可选的。当额外的监听器被禁用或无法绑定时（例如端口 8000 已被占用），主 Agent 监听器仍足以处理上传和下载；此时只记录一条警告，聊天不会停止。请绑定一个已挂载的持久化目录，并在设备上保留默认的 `/share` 路径。

首次在设备上推出该功能需要一次 OTA，其中包含更新后由平台负责的 `share.mount` 及与之匹配的业务软件包（Agent 可执行文件、Agent 单元以及 `aico-share-prepare.service`）。在较旧平台上只升级业务软件包是不够的：新的 Agent 服务依赖该挂载。版本发布分类会把新的挂载单元识别为平台变更，并推进兼容性契约。之后的 Agent/Web 更新可以走常规的业务软件包路径。开发流程不会烧录或部署任何设备。

## 上传与附加

每个请求只上传一个名为 `file` 的 multipart 字段，最大 100 MiB：

```bash
curl -F 'file=@report.csv' http://192.168.42.1:8080/api/files
```

`201` 响应包含元数据：

```json
{
  "kind": "file",
  "name": "report.csv",
  "path": "/share/report.csv",
  "size": 42,
  "mime_type": "text/csv; charset=utf-8",
  "download_url": "/share/report.csv",
  "modified": "2026-11-05T00:00:00Z"
}
```

在普通聊天请求中发送返回的路径：

```json
{
  "message": "Summarize this spreadsheet",
  "attachments": [{"kind": "file", "path": "/share/report.csv"}]
}
```

服务器会校验该文件存在于共享目录中，并从存储中获取其元数据。它把本地路径提供给 Agent，而不会把二进制数据嵌入到提供商请求中。文件引用会保留在聊天历史中。一个轮次最多接受 16 个附件，其中最多 4 张图片。
Web 的 **Add file** 选择器支持混合选择。图片通过 MIME 类型或图片文件扩展名识别，并沿用现有的视觉输入路径；其他文件（包括音频）作为本地文件上传。粘贴的图片使用同样的视觉输入路径。达到图片上限后，仍然可以继续添加其他文件，直到达到附件总数上限。
单个文件读取或上传失败不会中断所选的后续文件。输入框会报告失败和跳过的数量，并附上第一个失败原因。需要登录的响应会中止整批上传，并保留现有草稿。

### 聊天图片

随聊天轮次内联发送的图片（base64 `data`，来自选择器、粘贴或 API）仍会作为视觉输入送达模型，同时也会像通过 `POST /api/files` 上传一样保存到共享根目录：它们以 `shared_by: user` 列出，重名时追加随机后缀，没有图片扩展名的文件会根据 MIME 类型补上扩展名。Agent 会在图片旁边收到保存后的路径，历史记录条目中带有其 `download_url`。保存失败会被记录，但不会中断该轮次。在实时语音会话负责聊天期间发送的轮次会拒绝附件，也不会保存任何内容。

上传会以流的方式写入一个隐藏的临时文件，只有在完整的请求持久化之后才可见。重名的文件会获得随机后缀；已有文件永远不会被覆盖。上传失败会删除临时文件。启动时，共享存储准备流程会从共享根目录删除超过一小时的普通 `.upload-*` 文件，以在崩溃或断电后回收空间。较新的文件、子目录、符号链接和已发布的文件保持不变。
超大的上传返回 `413`；无效的 multipart 数据或文件名返回 `400`；存储故障返回 `503` 或 `507`。文件名不得为隐藏文件，不得包含路径分隔符或控制字符，长度不得超过 240 个 UTF-8 字节。

## Agent 如何看到共享文件

Agent 把 `/share` 当作控制器上的普通目录，通过 `shell` 和 Python 进行读写。附加的文件以其绝对路径的形式出现在用户消息中，送达模型。

要查看某个图片文件，Agent 会用其路径调用 `read_image`。该工具从 `/tmp` 或配置的共享目录（默认为 `/share`）读取普通的 PNG、JPEG 或 GIF（第一帧）文件。路径必须解析到所选目录内，共享文件继续遵守原有的隐藏文件和符号链接限制。每张图片都会先被完整解码，因此截断的文件会被拒绝，而不是被发送出去。GIF 的第一帧会放置在其完整画布上。长边超过 1568 px 的图片会被缩小并以 JPEG 发送，透明部分会被铺平到白色背景上；超过 25 MiB 或 4000 万像素的文件会被拒绝。图片会附加到下一次模型请求中，并带有一段说明文字，写明文件名并声明它不是所连接设备的显示画面，因此其坐标不会被用于 `touch_gesture`；它也不会被记录为最新的显示截图。对话记录中只保留路径、大小和格式。`read_image` 仅供后台 Agent 使用，Tools HTTP、MCP 和独立实时前台均不提供该工具。

每个用户轮次的状态消息中还带有一个 `shared_files` 条目，按最新优先列出 `/share` 下最近修改的 20 个文件，包括大小、`shared by user` 或 `shared by aico`，以及按配置时区显示的修改时间。与列表一样，隐藏条目和符号链接会被跳过。当文件更多时，该条目会说明这一点，Agent 会用 `shell` 列出目录。每次刷新最多检查 5,000 个条目，分批读取目录，并优先读取最近修改的目录；当共享目录更大时，该条目会说明它只涵盖已检查的文件。`/share` 中没有文件时，该条目会被省略。实时前台不会收到它；需要这些文件的设备工作在后台 Agent 中运行。

## 生成的输出和其他文件

Agent 被要求把可供下载的输出保存在 `/share` 下，并且每当回复中提到任何共享文件（上传的文件、聊天图片或它自己的输出）时，都要把它写成一个 Markdown 链接，链接文本为文件名，目标为其 `/share/` 路径，例如 `[report.pdf](/share/report.pdf)`。当路径片段包含空格、括号、非 ASCII 字符、`#` 或 `?` 时，需要对每个片段进行编码。例如，`report (final).pdf` 会变成 `report%20%28final%29.pdf`。

放入 `/share` 的任何普通文件（包括在 Agent 之外创建的文件）都可以立即使用，无需注册。支持子目录。`GET /api/files?path=outputs` 列出 `/share/outputs` 的直接子项；省略 `path` 时列出根目录。`/share/` 提供浏览器目录列表。隐藏文件、符号链接、特殊文件以及共享根目录之外的路径都会被排除。每个文件条目都带有 `shared_by`：通过 `POST /api/files` 上传的文件为 `user`，其他所有文件（例如 Agent 的输出）为 `aico`。上传记录保存在隐藏的 `/share/.uploads.json` 中；通过 API 删除文件时会删除其记录。在引入该记录之前上传的文件会被报告为 `aico`。下载使用 attachment disposition，支持 HEAD 和字节范围请求，并且不会把 HTML 或 SVG 作为同源内容执行。

Web 输入框有一个 **Add file** 控件。在 Web 对话中，附加的文件以及每个指向 `/share/` 下文件的链接（包括回复中裸露的 `/share/...` 路径）都会渲染为共享文件链接。鼠标悬停时会显示一个小的预览卡片，包含文件大小和所有者，并在支持时显示图片缩略图、文本文件的开头或缩小的 HTML 页面。点击会打开与检查器共享文件列表相同的预览对话框，其中带有下载按钮；带修饰键的点击（例如 Ctrl 或 Cmd）保持浏览器的默认行为，在新标签页中下载。预览支持图片（包括 SVG，以图片形式显示）、PDF、音频、视频、文本和 HTML。HTML 在不带 `allow-same-origin` 的沙箱框架中渲染：其脚本运行在一个不透明的源中，无法读取 Web UI、其存储或会话 cookie，开发板也会把它的请求当作跨站请求拒绝。在检查器中选择一个文件夹会在同一个对话框中打开它，列出其子文件夹和文件；选择某个条目会预览它或在该处打开子文件夹，**Back** 会返回到打开它的那个文件夹。聊天图片也会在消息中内联显示。手机 App 通过附件菜单和共享文件浏览器提供文件选择。iOS 会下载到临时文件并打开系统共享面板（包括“存储到文件”）；Android 会打开系统的保存文档选择器，并以流的方式写入所选位置。两个平台都不需要宽泛的存储访问权限。传输错误会显示在 UI 中；选择或取消选择器不会发送聊天轮次。

## 删除文件

`DELETE /api/files?path=<relative path>` 会删除共享根目录下的一个普通文件或一个空文件夹。路径格式与列表相同，例如 `path=outputs/report.pdf`。

| 响应 | 含义 |
|---|---|
| `204` | 已删除 |
| `400` | `path` 为空；共享根目录本身不能删除 |
| `404` | 未找到或不可删除：隐藏条目、符号链接（位于任意层级）、特殊文件以及共享根目录之外的路径都按不存在处理 |
| `409` | 文件夹中仍有条目；请先删除其内容 |
| `403` | 跨源的浏览器请求；同源的 Web 页面和原生客户端是允许的 |

删除操作绝不会在一个请求中删除整棵目录树，也绝不会跟随符号链接，因此 `/share` 中的链接无法被用来删除其他位置的文件。已经引用某个被删除文件的聊天消息会保留其链接；之后其预览会报告该文件已不存在，下载则会以 `404` 失败。删除使用与上传相同的访问规则（见下文）。

两个端口都使用与 Agent 相同的 `lanaccess.Guard`。LAN 客户端在 `/login` 或通过 `POST /api/auth/login` 登录；USB 客户端通过 `POST /api/auth/pair` 配对。浏览器发送 `aico_session` cookie，原生客户端发送 `Authorization: Bearer <token>`。该 cookie 适用于同一主机的 80、8080 和 8000 端口。下载 URL 不包含凭据，其本身也不授予访问权限。修改或清除设备密码会吊销现有会话。没有设备密码时不需要会话。

当 Web 上传收到 `401 login_required` 时，输入框会提供一个在新标签页中打开的登录链接，并保留草稿。登录后重新选择文件即可重试。目录链接和浏览器下载使用 guard 的常规登录重定向。`403 lan_access_disabled` 表示必须先启用 LAN 访问；登录无法绕过该开关。

App 通过 USB 配对，并在上传、列表和原生下载时发送其 token，无论通过 USB 还是 Wi-Fi 都是如此。下载会在打开保存选择器之前检查会话；原生请求会显式发送 token，并拒绝重定向。当 token 失效时，App 会通过 USB 重新配对。

Web 传输始终保持在当前源上，跨源的浏览器上传会被拒绝。所有已认证的设备会话都可以访问所有显式共享的文件；不存在按文件或按用户的 ACL。开发板提供的是明文 HTTP，因此只应在可信网络上启用 LAN 访问。不要在此目录中存放凭据，也不要把这些端口转发到不可信的网络。
