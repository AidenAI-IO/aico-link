# OTA 健康检查、数据兼容性与 A/B 回滚设计

OTA 升级只写入非活动的 A/B 槽位。写入之前，升级程序会为事务清单中列出的受保护配置文件创建一份
持久快照。只追加的用户数据保持原位。

重启后，OTA 健康聚合器运行只读的服务探测。必需探测失败时不会写入健康标记，因此本次启动尝试仍可
回滚。在这一恢复过程中，Agent 启动是可选的；Config Web 门户仍是必需的，以便修复损坏的 Agent
配置。成功写入标记后会提交所选槽位并清除待定事务。

回滚会选择上一个成功的槽位，并在提交 bootloader 选择之前恢复受保护的快照。早期启动恢复会协调
已完成和已放弃的回滚请求，而不会恢复无关的用户数据。Debian 生产镜像在 userdata 迁移之前通过
`aico-ota-recovery.service` 执行恢复，并使用 systemd OTA 健康聚合器进行服务检查。
