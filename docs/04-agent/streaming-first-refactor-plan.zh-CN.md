# Agent 流式优先重构：调研与实施方案（中文版）

> 本文是 [英文原版方案](streaming-first-refactor-plan.md) 的中文译本；技术标识、配置字段和参考链接保留原文。若后续两份文档存在差异，请以英文原版及实际代码为准。

**状态：** 产品范围已明确；本分支已实现兼容性保持的第一阶段基础契约和播放队列加固。剩余产品策略及后续迁移阶段尚未获批准。

**调研日期：** 2026-10-29。

**仓库基线：** `3aa92741d`，以及当日检查的工作区。

**范围：** 仅在现有 Go／C++ 运行时内改造 Agent 的 LLM、STT、TTS、realtime、工具／任务进度、Web 文本／事件、对话状态及音频服务。**产品语音输入始终来自板端麦克风。** 不开发浏览器、手机或桌面麦克风输入，不开发浏览器／手机实时音频，也不替换现有 Agent 运行时或将语音编排外包。现有桌面播放仍可用于输出侧开发／回归验证，不代表增加其他麦克风来源。不涉及重写 BSP、MCU 固件、OTA 系统或其他无关硬件服务。

## 1. 总体建议

将 Aico 重构为**以流式处理为基础的对话运行时**，保留现有 Go 守护进程、C++ 音频服务、服务商适配器、工具和记忆系统。建立**一套共享的生命周期与交付契约**，同时支持两条同等重要的路径：

1. **级联语音：** 流式 STT → LLM／工具循环 → 流式 TTS。
2. **原生实时语音：** 由服务商提供的双向语音到语音会话。

文本聊天使用同一套 LLM／工具引擎，不经过音频路径。两种语音引擎共享会话所有权、事件标识、取消、呈现、历史投影和可观测性；但不假设它们使用相同的服务商协议。

项目**不是从零开始加入流式能力**：现有代码已经支持 LLM 文本增量、TTS 音频、实时事件和开发板分块播放。主要缺口是完成／取消语义不统一、STT 只输出最终文本，以及板端音频的交付与背压契约薄弱。现有桌面播放也需要完整 WAV 才出声；对它的流式改造仅服务于输出侧开发／回归验证。

借鉴 LiveKit 的会话／轮次模型、Pipecat 的可中断帧处理，以及原生实时 API 的响应／内容项标识。**整个方案均不考虑替换现有运行时或外包语音编排。** 仅在现有 Go／C++ 系统内建立流式核心；外部框架和产品只作调研参考，不是可选实施路径。

### 成功标准

- 文本和 STT 临时转写结果在产生时即可显示。
- 对具备真正流式能力的配置，用户在生成结束前就能听到声音。
- 打断能及时停止本地播放、取消可取消的上游任务，旧音频不会流入下一次响应。
- 临时转写、已生成内容、完整模型响应以及实际显示／播放的内容有明确、不同的含义。
- 慢客户端、慢播放器、服务商故障和重连都有明确的内存／延迟上限，不会静默丢失数据或无限缓存。
- 只支持批处理的服务商仍可使用，但必须明确标记为降级；把完整结果包装成“流”不等于低延迟流式输出。
- 保留现有工具安全策略、前后台隔离、上下文压缩、服务商特有消息元数据和配置兼容性。

### 建议的首次交付

先交付一条**纵向打通的流式链路**，而不是全仓库接口大改名：板端麦克风语音／Web 文本 → LLM 增量 → 可播报文本投影 → TTS PCM → 板端播放，并打通打断及与实际交付一致的最终状态。现有桌面播放后端只用于开发输出验证，不作为采集源。之后加入来自板端麦克风的增量 STT，将原生 realtime 接入共享生命周期。

## 2. 证据与限制

本方案综合了仓库静态代码检查和服务商、产品及框架的官方文档。第 15 节列出的是有代表性的成熟系统，**并非经过市场份额测量的排名**。商业产品文档只能证明其对外暴露的行为，不能证明内部架构。

未进行服务商延迟基准测试、硬件声学测试或在线服务商兼容性测试。文中数值预算是**建议的验收目标**，不是实测性能或服务商保证。在线文档会变化；实施时应固定适配器使用的模型／API 版本，并保存协议测试样例。不能仅因调研文档展示了更新的模型就更改现有默认值。

## 3. 现有架构与明确缺口

### 3.1 现有链路

```text
传统语音
  设备 PCM 采集 ──> 可选的流式 STT 音频上传
                └──> 本地 VAD／完整话语回退路径
  最终转写 ──> Runtime.Run／AgentLoop
  LLM 回调 ──> 开头 <tts> 解析器 ──> TTS 适配器 ──> 播放
  完整 LLM 响应 ──> 工具解析／历史记录／下一次迭代

原生 realtime
  设备 PCM <──> realtimevoice 托管的服务商会话
  归一化事件 ──> 守护进程会话循环
               ├──> 播放
               ├──> 聊天增量／已完成的对话历史
               └──> 前台工具 ──> 独立后台任务

Web
  POST /api/chat ──> NDJSON 文本／进度事件
  GET /api/events ──> SSE 观察者事件
  音频附件／存档音频 ≠ 浏览器双向实时音频
```

下述是现状清单，不是目标范围。现有音频附件和本地录音后端不能作为此次改造新增其他语音输入来源的依据；目标只有板端麦克风。

### 3.2 审计发现

| 组件 | 当前观察到的实现 | 影响与迁移目标 |
| --- | --- | --- |
| LLM | [Runtime 流式接线](../../src/agent/internal/agent/runtime.go#L1156)在有 writer 时提供 `llms` 回调。[OpenAI 兼容解码器](../../src/agent/internal/agent/openai_compatible_model.go#L739)仍会组装完整响应。 | 保留历史与工具所需的最终结果聚合；用带类型的响应事件替代仅支持文本的回调耦合。聚合完整响应本身不是问题。 |
| Agent 循环 | [生成与解析](../../src/agent/internal/agent/agent_loop.go#L256)等待完整 `ContentResponse`，再决定是否执行工具。 | 提前输出进度，但绝不执行不完整的工具参数；保留校验与策略边界。 |
| STT | [`STTStreamUploader`](../../src/agent/internal/agent/stt.go#L23)接收 PCM，但 `Finalize()` 仅返回一个字符串。 | 流式上传不等于流式转写。分别表示可修订的临时结果、分段定稿和轮次结束。 |

| 批量 STT | [`TranscribeWAV`](../../src/agent/internal/agent/stt.go#L66)没有 context 参数，请求也未绑定当前轮次的 context。 | 取消信号必须能传递到 HTTP 请求和回退转写，而不只影响流式路径。 |
| TTS | [`TTSProvider`、`StreamSession` 和 `AudioSink`](../../src/agent/internal/agent/tts/provider.go#L15)已支持增量文本／音频以及播放端停止／排空。 | 演进现有抽象，不另建一套 TTS 子系统；区分输入结束、合成完成、播放排空与资源关闭。 |
| TTS 兼容 | [播报文本投影](../../src/agent/internal/agent/speech/text.go#L198)解析开头的 `<tts>` 块；[OpenRouter TTS](../../src/agent/internal/agent/tts/adapters/openrouter/session.go#L195)先读取完整 PCM HTTP 响应。 | 保留播报与显示分离；如实报告各适配器的实际流式粒度。 |
| Realtime | [`realtimevoice.Session` 及其事件](../../src/agent/internal/agent/realtimevoice/interface.go#L199)已经归一化服务商行为，并提供可选能力。 | 复用注册表、原生适配器、托管重采样及能力检测；从守护进程中提取共享生命周期策略，而不是迁移服务商协议实现。 |
| Realtime 编排 | [守护进程事件循环](../../src/agent/cmd/daemon/realtime_wakeup.go#L1444)承担准入、历史、播放、工具、通知和聊天桥接。 | 逐步将策略移入可测试控制器；保留响应 ID 过滤、取消确认、看门狗及服务商特有的事件顺序规则。 |
| 开发板播放 | [`AudioPlaybackSession`](../../src/audio_playback_session.cpp#L66)在最终块到来前即可播放；队列满时等待 200 毫秒，然后未重新检查容量就继续入队。 | 保留真正的分块播放；按音频时长／字节数严格限制队列，并明确饱和时的行为。 |
| 采集队列 | [录音队列入队](../../src/audio_record_session.cpp#L241)在达到 512 块上限时跳过新块且不报告。 | 统计丢帧、增加序号／时间信息和明确的音频断档策略；块数上限不是延迟预算。 |
| 现有桌面播放 | [`local_audio_playback.go`](../../src/agent/internal/agent/local_audio_playback.go#L64)先写临时 WAV，最终完成后才启动系统播放器。 | 将这一开发／回归输出端改为 live PCM，保留明确标注的缓存回退；这不代表允许桌面麦克风输入。 |
| Web 交付 | [聊天 fetch](../../src/agent/internal/agent/web_ui/scripts/chat.js#L33)使用 NDJSON。[`EventBroadcaster`](../../src/agent/internal/agent/event_broadcaster.go#L21)是尽力而为的广播器，订阅通道满时会丢事件。 | 保持 NDJSON／SSE 兼容；增加事件身份、重新同步和丢失检测，不把观察者广播器当作权威媒体／控制通道。 |
| 手机桥 | [桥接协议](phone-bridge.md#communication-method)承载命令与结果，不承载麦克风／扬声器媒体。 | 保持命令／结果通道；手机麦克风和媒体传输不在范围内，也不是延期功能。 |
| 后台任务 | [前后台隔离](foreground-background-agents.md#foreground-and-background-agents)将实时对话与排队的设备任务分开。 | 保留任务所有权和取消范围；取消语音不能隐式取消独立任务。 |
| 遥测 | [Episode 导出器](telemetry-langfuse.md#data-flow)已经异步发送 OTLP。 | 在现有 span 中加入流式里程碑和交付状态，不另建遥测栈，也不为每个音频帧创建 trace。 |

现有[语音文档](audio-features.md#tts-provider-usage)已经明确说明 TTS 接收 LLM 文本片段。若错误地认为“一切都是阻塞的”，既会破坏已有能力，也会漏掉真正的缺口。

### 4.2 共通的架构结论

1. **流式是一套生命周期，而非传输开关。** SSE／NDJSON／WebSocket 只能传送数据，不能定义打断或完成时的正确性。
2. **对话与执行要分离。** 响应迅速的前台语音会话不应同步等待耗时的设备操作。
3. **STT、LLM、TTS 的数据语义并不对称。** STT 会修订识别假设；LLM 输出文本及结构化工具数据；TTS 接收已确定的播报单元并输出音频。
4. **生成完成不等于播放完成。** 模型可能已经结束，播放队列里仍有数秒音频。
5. **服务商能力差异属于契约的一部分。** 统一概念，不强求所有服务商支持相同网络操作或尚未提供的功能。
6. **取消和背压应从架构第一天就纳入设计。** 接口名叫 `Stream`，不代表具备可控延迟。

### 4.3 唯一实施路径

**只在现有 Go／C++ 系统内建立流式核心。** 保留已经部署的设备服务、Agent 工具／记忆和服务商适配器，由 Aico 自行负责生命周期及协议测试。额外回调仅用于过渡适配，不能演变为永久的第二套架构。第 4.1 节的 LiveKit、Pipecat、Vapi、Retell、ElevenLabs 只提供设计参考，不再作为替换运行时或托管语音的候选路径。本方案不规划 WebRTC 网关、浏览器／手机媒体传输或桌面麦克风。

## 5. 目标架构与职责归属

```text
输入
  板端麦克风 PCM         Web 文本（无实时媒体）
          │                        │
          └────────────┬───────────┘
                           │
                       对话控制器
              准入、轮次策略、输出 epoch、
              打断、重连、会话级配置快照
                           │
             ┌─────────────┴─────────────┐
             │                           │
          级联引擎                   原生 realtime 引擎
          STT 事件会话               现有 realtimevoice 适配器
          LLM／工具运行              原生音频／文本／工具
          播报文本投影
          TTS 会话
             │                           │
             └─────────────┬─────────────┘
                           │
                   带类型的语义事件＋音频帧
                           │

                           │

```

### 职责归属规则

- 一个控制器负责一次对话的准入与生命周期转移。单麦克风／扬声器设备只有一个前台媒体所有者；本方案不表示可无限并发对话。
- 板端麦克风是唯一产品语音输入生产者，所有消费者的缓存都有明确上限。VAD 分支使用 16 kHz、每帧 512 个采样点；STT／realtime 分支使用协商后的格式。Web 文本不会变成 PCM。
- 一次运行负责模型尝试与工具调用。呈现协调器负责播放顺序、优先级、停止、排空和交付回执。
- 对用户请求的回复优先于排队的通知。任务更新与通知继续遵守现有的空闲准入及隐私规则，不混入所有助手文本流。
- 服务商适配器负责认证、传输封装、原生事件翻译及协议特有能力，不直接写 Web 历史。
- 历史投影持久化已提交的对话记录；独立交付记录区分已显示／已播放、被打断或状态未知。
- 遥测和观察者客户端不能阻塞麦克风采集或播放。

### 包边界：不立即重排目录

建议新增轻量底层包（暂名 `internal/stream`），只放值类型、ID、终态／错误约定、音频帧元数据和有界队列辅助函数。不能反向导入 `agent`、服务商 SDK 或 HTTP 处理器。

逐步将控制逻辑提取到 `internal/voice` 等包，只依赖窄接口和底层类型，不依赖 `agent.Runtime` 的具体内部实现。守护进程仍作为组装入口，负责提供 runtime、历史、工具、播放和 `agenttask` 适配器。现有 `tts`、`speech`、`realtimevoice` 保持原位，只有具体收益时才移动。提取守护进程循环时需避免形成导入环。

这里**不是**设计通用事件总线、分布式事件存储、Kafka 流水线或任意图执行器。高频路径使用直接的带类型连接；订阅只用于投影。

## 6. 共享流式契约

### 6.1 身份与顺序

语义事件包含带版本的信封和一个明确类型的载荷：

| 字段 | 含义 |
| --- | --- |
| `schema_version` | 对外事件 schema 版本；新增版本初步建议为 `2` |
| `event_id`、`sequence` | 稳定事件身份及对话 epoch 内由控制器分配的序号；重放游标同时包含 epoch 和序号 |
| `conversation_id`、`session_epoch` | 持久对话 ID 与当前连接代次；重连时推进 epoch |
| `turn_id`、`run_id` | 已接纳的用户轮次与执行任务；一次执行可包含多次模型响应／工具调用 |
| `response_id`、`attempt_id`、`item_id` | 分别标识一次模型响应、一次生成尝试和一个内容项；重试不得复用尝试 ID |
| `stream_id`、`output_epoch` | 输出轨道及其失效代次；停止输出不能同时使输入采集失效 |
| `call_id`、`task_id`、`parent_id` | 可选的工具／后台任务关联信息 |
| `occurred_at`、`received_at` | 服务商时间（若有）和本地接收时间；耗时使用本地单调时钟计算 |
| `origin`、`visibility` | 服务商／模块来源及允许投影：用户显示、播报、内部或诊断 |

并非所有事件都要求填满可选 ID；应按事件类型校验必填项。保留服务商原始 ID 为元数据；若服务商不提供 ID，由适配器分配本地 ID。不能根据到达顺序假定跨服务商的全局顺序，也不能虚构未出现的语音边界事件。

音频走独立的二进制／数据通道，但带有对应关联 ID、`frame_seq`、格式、采样数和**每声道采样点**计量的播放位置。内部 PCM 不要转为 Base64，也不应把每帧 PCM 写成历史事件。不同设备的时钟不能直接相减计算延迟。

Web 重同步必须原子地取得当前轮次快照及其事件水位，然后发送水位之后的事件。按投影过滤后的游标应考虑过滤规则：未交付的内部事件不等于公开事件丢失。进程重启后短期重放窗口失效，必须获取新快照，不得复用旧的 epoch／游标组合。

### 6.2 事件类别

| 类别 | 代表性事件 | 关键语义 |
| --- | --- | --- |
| 会话 | `session.ready`、`session.reconnecting`、`session.closed` | ready 表示协商后的配置已被接受，而不只是 socket 已连接 |
| 输入 | `input.speech_started`、`input.speech_stopped`、`transcript.updated`、`transcript.segment_final`、`turn.committed` | 临时转写可能修订；片段定稿和用户轮次结束并不相同 |
| 模型 | `response.started`、`text.delta`、`text.final`、`tool.arguments_delta`、`tool.call_ready`、`response.terminal` | 最终快照应替换／校正增量，不能把完整文本再追加一次 |
| 播报 | `speech.text_committed`、`audio.started`、`audio.ended` | 只有被批准播报的文本进入 TTS；音频产生结束不等于播放排空 |
| 呈现 | `playback.started`、`playback.progress`、`playback.drained`、`playback.stopped` | 回执带 epoch、内容项、已播放位置及测量来源／可信度 |
| 工具／任务 | `tool.started`、`tool.progress`、`tool.completed`、`tool.failed`、`task.updated` | 进度可选；最终结果需有关联并受大小限制 |
| 控制 | `cancel.requested`、`cancel.acknowledged`、`stream.discontinuity`、`stream.error`、`usage.updated` | 取消可绕开普通数据队列；错误区分可恢复与终止范围 |
| 执行 | `run.terminal` | 执行完成与呈现完成分开 |

把服务商暴露的推理内容及签名／不透明元数据与可见文本和播报隔离。保留现有重放要求和允许显示推理的设置，但不要把原始推理过程设为必须公开的流或遥测数据。

### 6.3 生命周期不变量

1. 每次响应尝试、合成、工具调用和执行都有且只有一个内部记录的终态：`completed`、`cancelled` 或 `failed`。
2. 仅通道关闭／EOF 而没有终态，应判为失败，不可视作成功。
3. 已失效 epoch 的迟到输出不得触达用户或进入新响应。迟到用量数据可更新统计，但不能恢复输出或重置看门狗。
4. `FinishInput` 只半关闭输入：后续仍可能有待交付输出。
5. `Flush` 提交目前缓存的播报文本，但不结束输入。
6. `Cancel` 是及时终止的请求，不代表远端已确认或本地播放已停止；两者要分别观察。
7. `Close` 是幂等的资源释放，不承担含混的 finish／drain 语义；若仍有工作，发起取消并设置关闭超时，不得永远等待已被放弃的通道排空。
8. 正常结束屏障包含最后一个相关事件／音频帧的位置，不可越过之前的数据；紧急取消／错误可绕过数据队列，因为它会明确使旧数据失效。
9. 每个可能阻塞的发送／读取／写入都需要 context 或超时；每条通道只有一个关闭所有者；释放所有权后禁止生产者继续发送。
10. “状态转换恰好一次”只是本地不变量，**不承诺网络恰好交付一次**。重放事件可重复，消费者应去重。

### 6.4 接口方向

下面仅是设计草图，**不能直接当补丁粘贴使用**。`ModelRequest`、`TranscriptEvent`、`AudioFrame` 等类型仍保留各模态自己的语义。

```go
// Runtime output is streamed while this call runs; final state remains available.
type Runner interface {
    RunStream(context.Context, TurnInput, EventSink) (RunResult, error)
}

type EventSink interface {
    Emit(context.Context, Event) error
}

type RecognizerSession interface {
    WriteAudio(context.Context, AudioFrame) error
    FinishInput(context.Context) error
    Events() <-chan TranscriptEvent
    Cancel(context.Context) error
    Close() error
}

type SynthesisSession interface {
    WriteText(context.Context, SpeechText) error
    Flush(context.Context) error
    FinishInput(context.Context) error
    Events() <-chan SynthesisEvent
    Cancel(context.Context) error
    Close() error
}

type Playback interface {
    WriteAudio(context.Context, AudioFrame) error
    FinishInput(context.Context) error
    Progress() <-chan PlaybackEvent
    Stop(context.Context, StopReason) error
    Close() error
}
```

保留原生 realtime 双向会话及其可选操作，不强行拆成 `RecognizerSession`＋`SynthesisSession`；只桥接到共享事件契约。如果更简单，TTS 音频仍可通过带类型的 sink 交付，而不必强制用事件通道；两种方式必须遵守相同的生命周期与所有权约定。

迁移期间，现有阻塞 API 可作为新流的聚合读取器继续提供兼容性。保留 `Runtime.Run`、`TranscribeWAV` 及旧 HTTP 响应格式。仅支持批处理的实现使用有界适配器，并声明 `output_granularity=final_only`；不能伪造逐 token 输出。

## 7. 分模块改造

### 7.1 LLM 与 Agent／工具循环

- 新增带类型的模型事件：文本、允许公开的推理、工具参数增量、工具调用就绪、用量、错误和终态。保留最终响应聚合、服务商特有的上下文、缓存元数据和签名推理内容。
- 所有前台模型调用内部都使用流式入口。后台上下文压缩、记忆提取等非交互任务可聚合流，但其事件必须保持内部可见，不能播报或进入聊天历史。
- 按响应／内容项管理输出，不共用一个可变的全局文本缓冲。保留工具循环迭代和转向指令之间的 reset／abort／finish 边界。
- 按调用 ID 和索引组装工具参数；仅在参数完整、合法、通过 schema 校验与策略审批后才执行。首轮仍沿用当前响应终态后执行工具的边界。等测试明确验证副作用后，才考虑参数刚完成就提前执行。
- 对支持的工具输出生命周期与有界进度。原子的 HID 操作只上报开始／结束即可；“所有模块流式”不代表要虚构工具进度。
- 保留现有取消／抢占通知、运行预算、上下文溢出恢复及前后台任务语义。

**重试规则：** 在尚未对外显示／播放、也未产生副作用之前，可以按现有策略自动重试。文本已经显示后，先明确标记／校正失败的尝试，才能给出替代响应；音频已经播放后，禁止不告知用户地从头重播。只有服务商明确支持并经过验证，或者显式发起新响应，才能恢复；否则报告部分失败。副作用结果未知时绝不自动重试。

### 7.2 STT 与输入轮次检测

为流式音频输入、临时转写、片段定稿、服务商话语结束检测、词级时间信息及取消／恢复分别声明能力；不能从 `SupportsStreamingUpload` 推断其支持实时转写输出。

使用带修订版本的转写片段：

```text
segment_id, revision, text_snapshot, is_final,
audio_start_sample, audio_end_sample,
可选 stable_prefix／词级时间戳／语言／置信度
```

新快照覆盖该片段之前的识别假设；空快照可以撤回假设。只有已经提交的最终结果进入持久用户历史；由唯一指定的轮次权威组件把最终片段组装成完整轮次。

- 尽早准备连接，但必须等服务商就绪后才发送音频；保留包括开头语音在内的有界就绪前队列。
- 如果超出就绪预算，应明确切换到有界批量回退或让输入轮次失败；绝不可跳过开头后仍将残缺结果标为成功。重放缓存音频时不得超出服务商允许的速率。
- 本地 VAD 继续负责活动检测和传统模式的结束判断；只有在明确选择时才交给服务商或语义检测决定轮次。原生 realtime 在需要时维持服务商权威。不能让两个提交器同时提交同一段输入。
- 将临时字幕流式发送到 UI。默认只有轮次提交后才启动权威 LLM／工具执行。提前预测生成属于未来可选优化：不得产生工具副作用、提交历史或在接受轮次之前出声，并应测量浪费的 token 与误判终点。
- 为批量转写加入 context 感知的取消。限制话语时长、字节数、初始化时长、最终结果等待时间和回退次数。明确无语音、不确定识别、只有噪声的误打断及部分网络丢失的行为。

### 7.3 播报文本投影与 TTS

保留现有**播报文本与显示文本分离**的设计。迁移时由开头的 `<tts>...</tts>` 解析器输出 `speech.text_committed` 片段；它是当前模型输出格式的适配器，不应要求所有下游组件重复解析同一标签。

不要同时修改提示词和流式基础设施。未来若更改提示词格式，需单独开展多语言质量评估。最终使用结构化内容还是显式文本标签，不影响流式契约的定义。

- 归一化块边界，不拆断 UTF-8 字符。刻意变更前应保留目前对跨块标签、缺少结束标签、工具响应边界、多余标签及重复播报抑制的处理。
- 对要求完整文本单元的适配器使用共享的可配置分句／分子句器。处理中文标点、缩写、数字、URL、Markdown、代码块及未闭合结构；不得播报工具 JSON 或内部推理。等待超时只能刷出安全的播报单元，不能随意读出不完整标记或半个数字。
- 区分原生增量文本 TTS、按句接收文本但逐块输出音频的 TTS、批量合成。服务商特有的缓冲和韵律控制留在适配器内部，但应暴露实际粒度及首音频里程碑。
- 将当前“关闭”行为拆为输入结束、合成结束、播放排空、资源关闭。不能让服务商读取循环无限期阻塞在慢速扬声器上。
- 保留服务商持有者的生命周期规则：配置切换只影响新会话；已开始的会话应正常结束或显式取消，不能半句话中途换声音／模型。
- 保留通知尾句、本地备用音频及工具调用播报规则。私人通知是独立的呈现项；部分内容已经播报后，不能再通过回退路径从头重播整条回答。

### 7.4 原生 Realtime 语音

复用现有服务商注册表、原生协议转换、媒体格式协商、托管重采样和可选接口。重构重点是提取共享的控制／呈现职责，而不是替换已有适配器。

- 将服务商原生 response／item／tool ID 映射到共享身份，保留重放、用量、打断及截断所需原始信息。
- 区分生成结束、服务商轮次结束、输入转写定稿和本地播放排空；某些原生事件可能缺失或乱序。
- 保留取消确认和“无进度”看门狗；后台持续传入的麦克风音频不能让卡住的响应被误判为仍有进展。
- 使用实际确认或明确标记为估算的播放位置进行打断／截断，不能把“写入 sink 的字节数”当成已播放位置。若打断后无法保证服务商上下文一致，应保守地重连并重放已确认历史。
- 原生 realtime 输入转写只用于展示，音频已经被服务商消费；不能再把转写文本作为第二次提示词提交。
- 保留服务商特有的工具继续生成规则；仅执行完整且通过校验的调用，关联并行调用结果，处理服务商取消的 call ID。
- 重连／会话轮换时，保留对话 ID、推进连接 epoch、恢复已提交的上下文，不重放过期音频或工具动作。仅在服务商声明并通过验证后才使用会话续接。

### 7.5 板端采集、音频格式与播放

保留现有带二进制载荷的 UDS 协议，不要通过 JSON 承载 PCM。向后兼容地增加帧序号、采集时间、排队时长、丢帧数、已播放位置，以及明确的停止／排空确认字段和能力协商；新旧客户端与音频服务必须能混用。

初期内部基线为 PCM16 小端单声道；但**不能强迫所有服务商都使用 16 kHz**。保留服务商／设备协商的采样率，仅在边界处重采样。跨帧保留重采样器状态；更换 epoch 时有意识地 reset／flush，并处理奇数字节片段。每条流的描述都要显式携带编码、声道数及采样率，而不是靠调用方猜测。

- 按字节数**和音频时长**限制播放队列，每次等待后重新检查容量。饱和时必须限时等待或明确返回错误，不能越过限制继续入队。
- 采集端不能因远端消费者慢而无限等待。倾向于有界、优先保留新数据的“丢弃最旧帧”策略，并附加断档计数；如断档会破坏本轮识别，需 reset、失败或明确回退，不能把受损输入标成完整可靠的转写。
- 区分服务已接收、已送入硬件，以及估算或确认已渲染的采样。现有“硬件尾音宽限”不是精确播放时钟；应披露播放进度可信度，并通过回环／声学测试验证。
- 将桌面完整 WAV 播放改为用于开发／输出回归的 live PCM sink，明确 stop／drain，并在需要时保留标记清晰的缓存回退。这仅涉及输出；不新增桌面麦克风，也不把文件式回退宣称为 realtime。
- 保留 Rockchip VQE／AEC 流水线。在开发板上完成同时采集／播放的回声与误触发测试之前，传统语音的全双工语音打断应默认不启用；物理按钮仍是可靠的打断路径。

### 7.6 Web 文本、手机命令及后台消费者

**文本 API：** 保留现有 NDJSON `/api/chat` 与 SSE `/api/events`。新增显式 v2 协商方式；两种传输序列化同一个语义投影，不能各自发明不同事件类型。旧版非流式客户端通过聚合读取继续工作。最终快照是替换，不是增量。

请求所有权需明确：按现有产品规则，拥有者的聊天连接断开时可取消其请求；观察者 SSE 断开**绝不可**取消运行。显式取消应以请求／运行／响应 ID 为目标，而不是取消“当前任何活动任务”。慢观察者应收到 `resync_required`，或被断开后从历史和活动轮次快照重新加载。只提供有界游标／epoch 重放窗口；进程重启或游标过期时重新取得快照，不能保证无限期重放事件。

**语音输入边界：** 由 `audio_service` 提供的板端麦克风始终是唯一产品语音输入。浏览器麦克风／实时音频、手机麦克风／媒体传输和桌面麦克风均不在本方案范围内，不作为后续阶段预留。Web UI 只保留文本／事件客户端职责；Phone Bridge 只承载命令／结果，不增加未来媒体会话扩展。

**后台消费者：** 任务、MCP／HTTP 工具调用者、调度器、记忆任务及基准测试只消费相关运行／进度投影，不需要接收 PCM。保留已有任务 ID、转向指令、上下文 lineage 与取消所有权。工具进度不能自动变成播报；由前台决定何时以及如何向用户概括。

## 8. 打断、状态与历史正确性

### 8.1 状态不是单一线性枚举

对话可以一边监听一边播报，应追踪相互正交的状态：

| 状态领域 | 状态 |
| --- | --- |
| 连接 | opening → ready → reconnecting／closing → closed |
| 输入轮次 | idle → speech／hypothesis → committed 或 discarded |
| 生成 | idle → running → cancelling → terminal |
| 播放 | idle → buffering／playing → draining → drained，或 stopped |
| 后台任务 | 保留已有独立的 `agenttask` 生命周期 |

响应进入终态时，播放可能仍未结束；播放期间也可能捕获新话语。由控制器决定准入，不能把这些事实压缩成一个含混的 `busy` 布尔值。

### 8.2 插话打断事务

1. 本地或服务商轮次策略接受打断，而不是对每个能量峰值都打断。
2. 原子地使当前输出 epoch 失效，后续迟到数据归为过期。
3. 立即停止／清空本地播放，不等服务商网络往返；记录播放位置以及该位置是实测还是估算。
4. 取消 LLM、TTS 和可取消的前台工具，并在服务商支持时发送原生取消／截断请求。后台任务继续运行，除非用户明确取消或更新它。
5. 分别记录本地停止与远端终态；服务商要求取消确认时，在确认到来前继续占有准入权。
6. 记录与实际交付一致的部分响应及打断原因；确认安全后才准入下一响应。缺少确认时按超时策略重连。
7. 误打断／没有转写结果时执行明确的产品策略：只有确定安全时才继续，否则请用户重说或保持监听；不能悄悄从头重放上一句。

### 8.3 历史与交付投影

保留现有用户／后台上下文隔离。增加交付元数据，而不是把所有临时事件都持久化为对话消息：

- 最终用户转写是持久输入；临时识别假设不入历史。
- 最终生成的助手内容作为文本／历史的权威响应，同时带终态及尝试 ID；失败的部分输出应注明状态，不能伪装为完整答复。
- 只有具备可靠对齐时，语音重放上下文才使用已交付的播报／片段。为诊断和显示保留独立的生成文本，明确区分“已生成”与“已说出”。
- 若有词级时间对齐及播放时钟，可截断到确认已播放范围；否则只提交已确认完整的片段，并添加“被打断／交付状态未知”标记，不能按字节比例估算词数并宣称精准。硬件渲染回执也不等于人一定听见了。
- 即使语音被取消，也要保留工具调用／结果对应关系和设备动作结果。确认播报被打断，并不意味着设备动作已经撤销。
- 通知播报保持私有，并按实际播放策略确认；不得泄漏进用户对话重放。
- 崩溃后保留已有的中断恢复机制，同时添加“交付未完成”状态；恢复时不得自动重播音频或重做产生副作用的工具动作。

## 9. 背压、错误与恢复

### 9.1 队列类别及暂定预算

以下数值只作为实验起点，未经测量不应变成配置默认值。PCM16 单声道在不计封装和复制开销时，16 kHz 约 32 KB／秒，24 kHz 约 48 KB／秒，48 kHz 约 96 KB／秒。

| 队列／操作 | 初始实验预算 | 饱和处理 |
| --- | --- | --- |
| 采集 → STT／realtime | 稳态队列 200–500 毫秒；就绪前最多 2 秒 | 报告断档，显式 reset／失败／回退；绝不静默丢弃语音开头 |
| 批量 STT 回退 | 初期每段话最长 30 秒，可按产品需要调整 | 超时要明确结束／拒绝；不能无限期将录音保存在内存 |
| 等待 TTS 的播报文本 | 同时限制字节与预估播报时长，初期约 2 秒文本 | 逐层传递有界背压；服务商无法暂停时明确失败，而不是无限堆积 |
| 输出 PCM | 初始播放缓冲 60–120 毫秒；目标排队 <300 毫秒，硬上限 1 秒 | 停止接收并向上游传递压力，到截止时间仍未恢复则取消；不能在正在播报的句子中静默断音 |
| 观察者事件 | 按数量／字节限制，提供活动轮次快照与有界重放 | 合并可覆盖的快照，或断开并重新同步；终态不能静默丢失 |
| 控制 | 小型保留邮箱＋取消信号 | 取消／停止不受媒体队列饱和影响；正常结束仍是有序屏障 |
| 单会话总缓冲 | 初始目标：应用层额外缓冲 ≤8 MiB | 超额明确拒绝；在目标硬件测量真实分配与复制量 |

服务商可能以快于实时的速度产生音频，且未必允许暂停。仅靠 TCP 流控无法保证应用层延迟；在 socket／SDK 的隐藏缓冲破坏实时性之前，适配器应报告无法跟上。原生 realtime 可能需要与级联 TTS 不同的具体预算，但队列类别和实测上限应一致。

### 9.2 错误分类与重试规则

使用带 `code`、`stage`、`retryable`、`response/attempt_id`、`partial_output`、`side_effect_state` 的有作用范围错误；服务商原始载荷必须脱敏。

| 故障 | 必须采取的行为 |
| --- | --- |
| 初始化／认证／配置 | 在采集／输出前失败，或明确采用已批准回退；错误密钥不能无限重试 |
| STT 就绪超时 | 有界缓存后走批量回退，或输入失败；不能丢掉开头后假装流式识别成功 |
| 对外输出前的服务商临时故障 | 在统一截止时间内进行有限的指数退避＋抖动；不能层层嵌套重试导致次数爆炸 |
| 已有部分文本／音频输出后失败 | 标记部分结果；不能不说明就把另一次尝试拼接／重播上去 |
| 下游饱和 | 遵守截止时间，取消相关输出；报告 `backpressure_timeout` 及队列指标 |
| 工具有副作用后超时／取消 | 独立于播报记录成功／失败／未知；重试前必须有幂等保证或先核对实际状态 |
| 取消后收到服务商事件 | 从用户呈现通道丢弃，仅保留允许的计费／诊断信息 |
| 重连／会话过期 | 推进 epoch，恢复已提交上下文；只在服务商明确支持并验证后续接 |
| 遥测不可用 | 对话继续；导出尽力而为、有上限，不能阻塞音频线程 |

## 10. 配置、能力与兼容性

继续使用 `model_settings` 和 `voice_settings` 下已有的命名服务商配置，不另建平行注册表，也不以重写用户 TOML 为前提。扩展 Config Web 当前使用的服务商元数据。

能力由**服务商＋模型＋API 版本＋模式**共同决定，并在会话 ready 时最终确认。区分静态已知能力与本次协商得到的能力。向运维和测试展示实际有效能力及降级原因：

| 领域 | 能力维度示例 |
| --- | --- |
| LLM | 文本增量、工具参数增量、用量报告时机、取消、续接 |
| STT | 实时音频输入、临时快照、片段定稿、话语结束检测、词级时间 |
| TTS | 增量文本、按句输入、增量 PCM、对齐、flush、取消 |
| Realtime | 轮次权威、打断权威、取消／截断、工具继续生成、上下文重放／续接 |
| Playback | 实时写入、停止、排空、队列时长、已播放位置精度 |

可考虑新增的策略项包括：`streaming_policy = "prefer" | "required" | "disabled"`、队列／超时上限、轮次检测权威以及全双工／插话打断模式。这些字段名称及位置需先通过配置 ADR（架构决策记录）确定；**文中并非声称这些配置已经存在。**

- `prefer`：支持时使用真正流式处理；批量回退必须明确可见。
- `required`：整条路径（包括播放器）无法满足要求时拒绝该配置，不能静默降级。
- `disabled`：使用兼容聚合行为，而不是永久维护第二套引擎。

弃用过渡期通过适配器保留 `voice_streaming_tts_enabled`、输入模式、请求 ID、事件名及 API。热更新使用每会话配置快照；模式／媒体格式变化只在安全边界重启。先发布向后兼容的 UDS／HTTP 扩展，再升级客户端。回滚版本必须能读取新写入的历史，并忽略新增交付数据。

输入来源校验独立于播放端选择。语音采集只能通过 `audio_service` 使用板端麦克风；板端音频不可用时应明确拒绝启动语音，不能自动回退到桌面、浏览器或手机麦克风。批量 STT／回退可以处理板端采集得到的 PCM／WAV，但上传音频不能成为另一种产品语音输入。保留存档音频查看和隔离的离线测试样例，不把它们变成实时输入通路。实施时应记录并拒绝不兼容的旧输入配置；兼容策略不能覆盖这一固定输入边界。本次文档修改不改变当前已部署行为。

## 11. 安全与可观测性

### 11.1 安全要求

- 内容一旦显示或播出就难以收回；可见性、脱敏和安全策略必须在相关输出投影**之前**执行，而不是仅在最终结果持久化时处理。
- 禁止播报原始内部推理、工具参数、凭据或不可信标记；现有工具校验／审批依旧是权威。
- 对帧、事件、工具参数、转写和缓存内容设置大小上限；分配内存前先校验长度和格式。
- Web 文本／事件端点需要认证后的所有权、来源校验、适用场景下的 TLS、速率限制和会话级取消权限。服务商密钥留在服务器，不规划客户端直连服务商的实时媒体路径。
- 音频／转写保留和遥测上传是需要明确决定的政策。默认不新增原始音频或私人转写上传；维持当前按需启用的遥测，并对诊断材料脱敏。

### 11.2 指标与 Trace 结构

扩展现有 Episode／OTLP 集成，保留稳定命名和每次调用对应的模型／用量归属。保留当前 OTLP 契约和 ingestion 版本；本方案不要求升级 Langfuse SDK 或平台。实施埋点时参考最新 Langfuse 指南 [S13]。

按 conversation 组织 turn／run；后台任务使用关联关系，不要把“派发”与“执行”重复记录为两个相同工作实体。重点阶段包括采集、话语结束判断、STT、每次模型尝试、工具执行、TTS 和播放。只记录汇总和里程碑，不为每个 token／音频帧建 span。

至少记录：

- 用户最后一个语音采样点、接受轮次结束的时刻、首个／最终转写。
- LLM 请求、首个可见文本、首个允许播报文本、最终响应。
- TTS 请求、首个解码 PCM、首个实际渲染音频、最后一个实际渲染音频。
- 检测到／接受打断、本地停止、远端取消确认。
- 队列时长／字节、溢出／断档、播放欠载、过期事件丢弃。
- 服务商／模型／API 版本、模式、格式、网络区域、token／音频用量、重试、回退、冷／热启动、终态／交付状态及任务结果。

主要语音延迟指标应是 `end_of_user_speech → first_rendered_audio`，并同时记录 `turn_commit → first_rendered_audio`，以单独分析话语结束检测带来的延迟。不要把服务商首音频时间称为“用户感知延迟”。确认性短语与首次有效回答应分别统计，避免用填充语音掩盖 SLO。

### 11.3 建议验收预算

对指定服务商／模型／区域、连接已预热、不调用工具且测试网络健康的轮次，以以下目标作为假设；在阶段 0 建立实测基线：

| 指标 | 初始目标 |
| --- | --- |
| 用户说话结束 → 首段有效语音实际播放 | p50 ≤1.0 秒，p95 ≤1.8 秒 |
| 接受打断 → 板端播放停止 | p95 ≤150 毫秒 |
| 排除服务商／网络后的本地处理开销 | 目标硬件上每轮 p95 ≤100 毫秒 |
| 首段流式音频相对于生成结束 | 在支持流式的测试样例及在线冒烟测试中，音频早于响应完成开始播放 |
| 停止确认后的过期输出 | 已失效 epoch 的帧呈现数量为零 |
| 重复工具执行／重复播报片段 | 确定性故障／重放测试中为零 |
| 会话内存与 goroutine | 队列有界；1 小时持续运行测试中不持续增长 |

工具密集、冷启动、弱网和批量回退场景分别统计分布。不能用虚构的服务商 SLA 阻断发布；应在基线测量后批准阈值，并明确报告回归。

## 12. 验证策略

### 12.1 优先建立确定性测试

使用可控时钟、脚本化服务商事件及模拟播放回执，让以下测试不依赖网络时序或付费 API：

1. 任意 token／UTF-8／标签分块、多工具调用、推理与内容隔离；最终快照与增量聚合一致且不重复播报。
2. STT 假设替换／撤回、一个话语包含多个最终片段、就绪延迟、空语音、初始化／最终结果失败及有界回退。
3. TTS flush 与 finish 区别、分句／韵律边界、慢合成／慢播放、奇数 PCM 字节块、重采样连续性与格式切换。
4. 首 token 前、工具参数生成中、音频合成中、生成结束但播放未排空时，以及恰好响应完成时打断。
5. 数据队列满时收到取消、写入卡住、没有终态就 EOF、重复／乱序事件、缺少 ID 的 realtime 事件。
6. 断线／重连／凭据租期结束、旧 epoch、缺少取消确认、已显示输出后重试、交付未知时的崩溃恢复。
7. 取消期间已完成的工具副作用、并行调用、后台任务继续运行、转向指令修订、通知／告别语的播放准入。
8. 新旧 HTTP／UDS 兼容、慢 SSE 消费者、快照重同步、观察者断开与请求所有者断开的区别。
9. 会话级格式／服务商热更新隔离、非法帧／超大载荷、并发／竞态与 goroutine 泄漏。
10. 板端唯一输入校验：拒绝其他麦克风／输入配置；`audio_service` 不可用时不会选中本地录音器；板端录音的批量回退有效，离线样例不能启用产品输入通路。

保留并扩展现有[播报解析](../../src/agent/internal/agent/speech/text_test.go)、[STT 最终结果](../../src/agent/internal/agent/stt_streaming_session_test.go)、[Anthropic 推理重放](../../src/agent/internal/agent/anthropic_thinking_replay_test.go)、[realtime 准入](../../src/agent/cmd/daemon/realtime_busy_test.go)及[开发板播放](../../tests/audio_playback_session_test.cpp)测试；不能用只覆盖成功路径的流式测试替代。

为每个已交付的适配器添加脱敏协议样例，在元数据中固定模型／API／协议版本，把“不支持某项能力”也纳入矩阵。现有服务商继续受支持，即使部分仍明确为 batch-only。

### 12.2 真实工作流验证

- 开发板：使用板端麦克风，验证长回复在生成结束前出声；反复打断，确保下一轮绝不播放旧音频；尽可能测实际声音／回环，而不只是 socket 时间戳。桌面输出测试仅使用已获授权的板端录音或隔离测试样例，不能使用桌面麦克风；这类检查与板端声学验收分开。
- 中文、英文及中英切换：停顿、自我更正、数字、人名、附和语、噪声及长话语；同时评估 STT 准确度、播报可懂度和延迟。
- 至少验证一个具备明确 ID／取消语义的现有原生 realtime 服务商，以及事件语义不同的 Gemini；之后覆盖全部已交付适配器。TTS 至少覆盖原生增量路径和缓冲／批量路径。
- 慢网／不稳定网络、连接冷启动、服务商限流、漏检语音边界、扬声器播放时的 AEC，以及持续一小时的会话。
- 板端语音活动期间同时测试文本客户端、浏览器观察者、后台任务、通知和配置热更新。浏览器实时音频、手机音频和桌面麦克风不在范围内，不设相关验收矩阵。

付费服务商测试和录音需要已获批准的凭据、成本上限及数据授权。确定性 CI 不依赖个人密钥。

## 13. 迁移计划与交付门槛

采用渐进替换方式：新契约先包装现有实现，再逐项迁移职责。不做一次性重写，也不顺便进行无关包重命名。初步规划为：**在具备开发板硬件及服务商访问条件下，2–3 名工程师、8–12 周**。这是规划范围，不是交付承诺。浏览器／广域网语音、手机媒体、桌面麦克风和运行时替换明确排除，不另列为后续估算项目。

| 阶段 | 工作与主要改动点 | 完成门槛 |
| --- | --- | --- |
| **0 — 基线与 ADR**（约 1 周） | 冷／热启动时间线、实际能力矩阵、板端麦克风／扬声器测量；确定事件身份、职责、队列和历史策略 | 可复现基线、批准的范围及 SLO 假设；行为不变 |
| **1 — 核心契约**（1–2 周） | 底层流类型、聚合兼容层、attempt／epoch 身份、有界队列、终态规则、可控时钟测试；桥接现有 runtime writer 和 realtime 事件 | 契约测试通过，已有调用方和事件格式不变 |
| **2 — 输出链路纵向打通**（约 2 周） | LLM → 现有播报解析器 → TTS → 呈现协调器；拆分 close／drain；板端队列硬上限和停止回执；桌面开发输出端 | 板端长回复生成结束前出声；队列满时仍能及时取消；工具播报不重复 |
| **3 — 流式输入**（1–2 周） | STT 转写事件、就绪前缓冲、可取消的批量回退、轮次权威与实时字幕 | 保留开头音素；假设修订正确；每段话语只提交一个有效轮次 |
| **4 — Realtime 收敛**（约 2 周） | 将守护进程策略提取到接口后；复用呈现／历史／遥测；保留原生适配器和前后台行为 | 重放／取消／看门狗矩阵通过，覆盖事件缺失／乱序 |
| **5 — 客户端发布与加固**（1–2 周） | v2 事件协商、观察者重同步、能力 UI、混合版本兼容、长时间及多语言测试；删除确认不再使用的兼容层 | 实测验收、降级模式文档、回滚演练完成 |

只有契约稳定后才能并行推进。建议一人负责控制器／运行时、一人负责 STT／TTS／服务商一致性、一人负责 C++ 板端音频和文本 UI；硬件／QA 工作需要贯穿全过程。

### 可独立评审的具体工作项

1. 增加流身份／终态测试样例与能力清单，不改变行为。
2. 在已有 LLM 回调周围加入带类型的事件及阻塞聚合适配器。
3. 增加 generation／attempt 失效机制和输出后重试测试。
4. 提取呈现所有权，明确 finish／drain／stop。
5. 修复开发板队列饱和处理，加入丢帧／播放进度协议字段和兼容测试。
6. 为桌面开发输出端实现 live PCM，不增加桌面采集。
7. 桥接现有播报解析器／TTS 适配器，保留工具及通知播报规则。
8. 增加 STT 就绪缓冲与可由 context 取消的批量转写。
9. 为现有流式 STT 适配器加入修订／定稿／轮次事件。
10. 保留适配器，将原生 realtime 的策略迁入控制器。
11. 增加 Web v2 投影、游标／快照恢复及有效能力 UI。
12. 增加端到端指标、故障／持续运行套件、灰度开关及迁移文档。

主要改造入口是现有 [runtime](../../src/agent/internal/agent/runtime.go#L1156)、[audio dialog](../../src/agent/internal/agent/audio_dialog.go#L886)、[realtime 守护进程循环](../../src/agent/cmd/daemon/realtime_wakeup.go#L1444)、[TTS 契约](../../src/agent/internal/agent/tts/provider.go#L15)和 [STT 契约](../../src/agent/internal/agent/stt.go#L13)。不要以移动数百个文件或全局替换 `langchaingo` 作为第一步。

### 灰度与回滚

- 使用临时的会话级引擎功能开关；一个会话只用一套引擎。支持设备／用户灰度和快速回退旧引擎，不在半句中切换。
- 影子验证只处理纯事件归并／投影，并使用脱敏样例或录制数据。未经实验批准及授权，禁止双跑工具、同时播两路声音或把实时音频送往第二家服务商。
- 先交付服务器／协议兼容性，再开放客户端选择新版本。直到所有支持客户端迁完且回滚经过验证，才移除旧投影。
- 历史新增交付元数据或带明确版本的 sidecar，不做破坏性迁移；验证旧二进制仍能正常工作。
- 出现旧语音泄漏、重复动作、取消变慢、内存持续增长或任务成功率下降时回滚，不只在进程崩溃时回滚。
- 只有达到实测行为一致并经过约定支持窗口后，才删除兼容代码；不能永久维护两套编排实现。

## 14. 已确认范围与待决事项

### 已确认的产品边界

- 只在现有 Go／C++ 运行时内建立流式核心，不替换为第三方框架，不外包语音编排。
- 通过 `audio_service` 使用板端麦克风是唯一产品语音输入，不只是首版默认值；不接入浏览器、手机或桌面输入。
- 不开发浏览器实时语音或手机媒体路径；Web 文本／字幕／事件和 Phone Bridge 命令／结果保留原有职责。

### 仍待批准的策略

仅以下剩余产品取舍需要负责人批准：

| 决策 | 推荐默认值 | 为什么需要确认 |
| --- | --- | --- |
| 是否强制所有服务商支持真正流式 | 保留当前全部服务商，标记仅最终结果的适配器，并提供 `required` 策略 | 不支持的服务商／模型组合无法承诺真正流式 |
| 默认语音引擎 | 保留当前选择，同时支持级联与原生 realtime | 质量、地区、成本、工具控制和语言覆盖不同，尚无实测的通用最优选择 |
| 传统语音插话打断 | 默认按钮打断；AEC 验证后用户主动启用全双工 | 误打断和回声取决于真实硬件与声学环境 |
| 打断后的对话历史 | 保留生成内容及状态；语音重放只使用有交付依据的播报＋打断信息 | 会改变用户可见行为和模型上下文 |
| 延迟／成本目标 | 先测基线，第 11 节仅作为初始假设 | 激进结束判断／预测生成可能降低延迟，但损害准确性并增加成本 |
| 区域验证 | 优先已有中国可访问服务商，另加一条全球参考路径 | 端点地区／代理路由会显著影响感知延迟及隐私约束 |
| 人力与发布 | 2–3 名工程师、8–12 周核心分阶段迁移、会话级灰度 | 开发板硬件、服务商访问和兼容范围决定工期 |

剩余策略获批后，先编写简短的契约 ADR，再开展阶段 0／1。已确认的范围不等于授权全部实施，也不等于授权合并发布。
