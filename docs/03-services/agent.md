# Agent: AI Assistant Service

`agent` is the core Go service that provides the Agent Web UI, HTTP APIs, and optional device-side voice interaction. It orchestrates model calls, tool execution (HID control, screenshots, audio playback), and conversation sessions.

## Default Parameters

| Parameter | Default Value |
| --- | --- |
| Config | `/userdata/agent/agent.toml` |
| Log | `/userdata/agent/log/agent.log` |
| Binary | `/usr/lib/aico/agent` |
| Session data | `/userdata/agent/` |

## Startup

```bash
systemctl start aico-agent.service
systemctl status aico-agent.service
systemctl restart aico-agent.service
```

## Input Modes

The HTTP server and Web UI run in every input mode:

- **`input_mode = "stt"`**: Runs the device audio loop in parallel with the HTTP server, using `audio_service`, VAD, the selected STT provider, the model, and the selected TTS provider.
- **`input_mode = "realtime"`**: Runs the configured realtime voice model directly; realtime activation is selected explicitly by this mode.

The daemon flag `-classic-voice` (default `true`) controls whether `stt` mode
may hold voice conversations. Hosts without the VAD models, such as the Docker
image, start the Agent with `-classic-voice=false`. In `stt` mode the Agent
then builds no audio dialog and never starts the VAD or Smart Turn helpers:
wakeups from the MCU or GPIO keys are ignored, `GET /api/realtime/voice`
reports `available: false` so the Web UI offers no voice button, and a browser
voice start is refused. Typed chat keeps working and replies with text. The
setting persists across configuration reloads, and `realtime` mode is not
affected. The Agent logs one startup line when the flag is off.

## Task history

In the Agent Web UI, open **Task history** under **Background tasks**. The
list shows each recorded task's status, start time, elapsed time, backend
tokens, cached and uncached input, output, cache hit rate, and cost.
**Backend tokens** sums the task's backend model calls, including cached
input. In Realtime mode, **Reply token usage** on a chat message comes from
the response generated by the realtime model. The cache hit rate is cached
input divided by total input. On narrower screens,
each task shows the same fields across several lines. Select a row for
the tool-call timeline and cost source. Expand a long tool result to read
the recorded text in the dialog. When the list is empty, the sidebar shows
**No task history.** The history uses the Agent's local episode records and
follows their retention policy.

Resumed background tasks recorded with a task ID appear as one item.
Elapsed time includes queueing and time between executions. Older episodes
without a task ID appear as individual executions.

The Agent uses each model call's provider-reported cost first, then an estimate
already available to [Langfuse telemetry](../04-agent/telemetry-langfuse.md),
then [models.dev](https://models.dev/) token prices. It identifies the pricing
provider by the API endpoint and matches the complete model ID. APIBest's
`gpt-6-luna` can use the corresponding OpenAI entry as a reference price.
The Agent applies context tiers to each call and records the amount and
matched tier with the episode. For older episodes, it uses recorded totals
when they determine the applicable rates. A backfilled cost is marked partial
when some calls lack recorded usage or an older multi-call record has unknown
coverage.

On startup or a model change, a recognized endpoint can trigger a background
catalog load. Reasoning metadata and cost estimates share the same catalog
load in the Agent process. After a failed load, a later model run can retry
after a one-minute backoff. The Agent reuses a local snapshot for up to 24
hours at startup. Task history uses local data even when telemetry export
is disabled. The list displays a dash when no amount is available and
appends `+` to a partial total. Task details show the cost source.

The read-only endpoints are `GET /api/agent-tasks/history` (with
`?before=<next_cursor>` for older records) and
`GET /api/agent-tasks/history/{id}` for details.

## Configuration

The service reads `/userdata/agent/agent.toml`. Provider tables define named provider instances, and the corresponding selection table references one of those names:

```toml
[voice_settings.mode]
input_mode = "stt"

[model_settings.providers.openai-main]
type = "openai"
api_key = "$OPENAI_API_KEY"
# base_url = "https://api.openai.com/v1"

[model_settings.model]
provider = "openai-main"
model = "gpt-5.5"
# temperature = 0.2
# max_response_tokens = 0  # 0 = provider default

[voice_settings.classic.audio]
# socket = "/run/audio_service/audio_service.sock"
# backend = "auto"

[advanced_settings.hardware.hid]
# keyboard_device = "/dev/hidg0"
# mouse_device = "/dev/hidg1"
# android_keyboard_device = "/dev/hidg2"
# frame_socket = "/run/frame_service/frame_service.sock"

[voice_settings.classic.stt.providers.openai-main]
type = "openai-whisper"
api_key = "$OPENAI_API_KEY"
model = "whisper-1"

[voice_settings.classic.stt]
provider = "openai-main"

[voice_settings.classic.tts.providers.minimax-main]
type = "minimax-cn"
api_key = "$MINIMAX_API_KEY"
voice_id = "male-qn-qingse"

[voice_settings.classic.tts]
provider = "minimax-main"
speed = 1.0
```

Built-in model provider types include `openai`, `anthropic`, `openrouter`, `kimi`, `kimi-cn`, `volcengine`, `deepseek`, `gemini`, and `ollama`. Anthropic Claude can be accessed directly through the native `anthropic` provider or through a compatible provider such as OpenRouter. Google Gemini models use the native `gemini` provider, which speaks the Interactions API.
