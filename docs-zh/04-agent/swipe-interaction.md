# 滑动交互

Aico 通过 USB HID 控制手机滚动和选择器滚轮，同时通过 HDMI 截图观察结果。由于它收不到原生的无障碍事件或滚动事件，每个手势都必须根据可见屏幕来验证。

## 约束

| 能力 | Aico 的行为 |
| --- | --- |
| 触摸确认 | 根据操作后返回的截图推断是否成功。 |
| 控件数值读取 | 从屏幕上读取可见数值；没有原生的选择器数值 API。 |
| 滚动边界检测 | 比较操作前后的截图，并检查结果页面。 |
| 惯性控制 | 使用有界的手势并重新观察，而不是假定精确的位移量。 |

JPEG 噪声、动画帧和重复内容使精确的像素位移不可靠。应把滚动视为一个“观察-操作-验证”的迭代循环。

## 工具

### `touch_gesture`

普通触摸交互使用标准的 `type` 形式，包括点按、长按、滑动、滚动以及两阶段拖动。原子 `actions` 是一个低频使用的高级选项，用于标准手势类型无法表达的、不间断的自定义接触序列。各操作在同一个输入会话中按顺序执行，因此接触在等待和移动期间始终保持按下：

```json
{
  "actions": [
    {"action": "touch_down", "point": {"x": 500, "y": 700}},
    {"action": "wait", "ms": 80},
    {"action": "move_to", "point": {"x": 500, "y": 300}, "speed": 2500},
    {"action": "touch_up"}
  ]
}
```

操作词汇刻意保持精简：

- `touch_down`：开始一次接触，需要 `point`。
- `move_to`：移动到 `point`，保持当前接触状态。可选的 `speed` 以每秒归一化坐标单位计，并根据前一个点推算移动时间。`duration_ms` 会覆盖 `speed`；两者都省略时，保持原有的瞬时移动。
- `wait`：等待 `ms` 毫秒，不改变接触状态。
- `touch_up`：释放当前接触；`point` 可选。

坐标使用归一化的 `0..1000` 范围。一个程序至少包含一个操作，并且必须以 `touch_up` 结尾；每个声明的操作时长上限为 30 秒，所有声明时长之和上限为 60 秒，程序最多包含 128 个操作。HID 和 ADB 在发送任何输入之前，都会对提交的程序及展开后的运动曲线（包括其释放尾段）检查这些限制。受支持的单对象 `type` 形式仍是普通交互的默认方式；不支持 `type:"drag"`。

移动一个可拖动目标有意拆分为两次工具调用。绝不要用原子 `actions` 替代这一流程。始终使用以下顺序：

1. 在目标当前的中心点调用 `{"type":"drag_start","point":{"x":400,"y":500}}`。
2. 让 `drag_start` 完成其内部的屏幕稳定等待。当其结果报告 `screen_stable=true` 时，检查返回的稳定截图并确认最终目的地点。不要根据中间结果或 `screen_stable=false` 的结果选择目的地。当 `screen_stable=false` 时，运行时会自动把接触移回最初的 `drag_start` 点并释放；检查返回的截图，然后从第 1 步重试该流程，而不是调用 `drag_release`。
3. 用该确认点调用 `{"type":"drag_release","point":{"x":750,"y":500}}`。

`drag_start` 先按住 500ms，然后以每秒 500 归一化单位的速度（一次 400ms 的插值移动）沿有界的轴向恰好移动 200 归一化单位以激活拖动，并且在屏幕稳定后不释放。`drag_release` 直接移动到目的地，保持 200ms，然后释放。不要在这两次调用之间发出无关的输入操作。稳定屏幕等待和最终截图都在 `drag_start` 内部完成；单独调用 `wait_for_stable_screen` 不属于正常流程。之前的单次调用 `type:"drag"` 手势已被移除。

在 Android ADB 后端上，提供方通过 `getevent -lp` 发现物理触摸屏及其绝对坐标范围，然后发出 `sendevent` 程序，在原子等待/移动期间以及跨越 `drag_start`/`drag_release` 边界时保持接触。这要求 Android shell 用户对所选的 `/dev/input/event*` 设备具有写权限。当设备权限或 SELinux 禁止原始注入时，提供方会回退到 Android 的 `input touchscreen motionevent DOWN|MOVE|UP` 原语；如果这也不可用，原子操作会返回 `module_unavailable`。HID 是通过 `input_backend=hid` 单独选择的另一种方式；ADB 提供方不会自动切换到 HID。

对于普通列表、轮播、地图以及其他可自由滚动的界面，使用 `type:"swipe"`：

```json
{
  "type": "swipe",
  "start": {"x": 500, "y": 650},
  "end": {"x": 500, "y": 350}
}
```

`speed` 可选，默认值为每秒 `2500` 归一化坐标单位。滑动可接受 `start` + `end`，或 `start` + `direction`（`up`、`down`、`left`、`right`）。`duration_ms` 可选：与显式 `end` 一起使用时，它会覆盖计算出的时长；与 `direction` 一起使用时，它按 `speed * duration_ms / 1000` 决定移动距离。不指定时长时，方向滑动会一直移动到相应的屏幕边缘。`hold_before_ms` 和 `hold_after_ms` 可选择在按下后和释放前增加停留时间（默认 0），`steps` 可选择控制 HID 插值次数（默认 24）。例如，`{"type":"swipe","start":{"x":500,"y":800},"direction":"up","speed":2500,"duration_ms":300}` 的终点是 `{"x":500,"y":50}`。

归一化坐标在每个轴上使用 `0..1000` 范围。HID 操作工具会在屏幕稳定后返回操作后的截图。

## 选择器工作流

选择器列使用标准的 `touch_gesture` 滑动。专用的 `wheel_nudge` 工具、行间距检测器以及仅用于选择器的执行策略都已移除。

1. 从最新截图中读取中间选中的值以及相邻行的顺序。位于中间以外的可见值并未被选中。
2. 把目标行朝中间移动：目标行在上方时需要手指向下滑；目标行在下方时需要手指向上滑。保持最终请求的目标不变。
3. 从目标列内部、靠近合适的内侧边缘处开始。许多控件在指针离开其边界后仍保持接触，因此终点可以超出该列，但要留在屏幕内，并与物理边缘保持一定距离。
4. 根据可见的行间距估算移动距离，并根据观察到的数值变化进行校准。离目标较远时使用较长的移动距离，接近目标时使用较短的修正。时间参数保持默认，并省略 `hold_after_ms`。
5. 在每张返回的截图中验证居中的值。即使 `screen_changed=false`，可读数值发生变化也算有进展。如果移出区域会取消手势，则对该控件缩短下一次的路径。
6. 保存前验证所有请求的列。不要点按选择器的行，也不要通过文本输入来调出编辑器。如果数值无法读取，或者重复的较短修正无法收敛，则停止。

## 共享运动曲线

`src/agent/internal/agent/mnk/motion_profile.go` 负责五次加速/制动曲线、释放资格以及归一化终点拆分。标准 HID 滑动、带时长的 HID 原子接触移动以及 ADB 触摸程序都复用它。新的手势工具应调用 `SwipeWithOptions` 或 `TouchActions`，而不是自行实现报告轨迹。各后端保留各自的事件编码和调度：HID 使用单调时钟；ADB 保留请求的休眠间隔，但进程/注入开销可能会增加实际耗时。

符合条件的内容手势至少使用 180ms 的主运动，随后在最后两个归一化单位（不超过最后一段的一半）上进行 100ms 的真实低速移动。这样是逐渐逼近精确终点，而不是停在一个静止坐标上。从屏幕边缘起始的手势以及显式的终点停留不使用释放尾段。原子瞬时移动以及会改变终点的释放保持原有语义。鼠标滚轮事件和专用的两次调用拖动 API 是独立的操作。

iOS `app_switch` 快捷操作在按下后等待 80ms，向上移动 350ms，释放前等待 200ms：编程的接触时间为 630ms，而不是 1750ms。稳定屏幕观察和 HID 开销另计。

iOS `close_app_from_recents` 快捷操作从居中卡片底部附近的 `(500,780)` 开始，在 180ms 的主运动段内移动到 `(500,50)`，并保持共享的低速释放曲线。加上最初 80ms 的等待和 100ms 的移动释放尾段，编程的接触时间为 360ms。更长的路径为慢速释放的关闭操作提供了更多移动距离。之前从 `(500,500)` 到 `(500,120)` 的路径在本地 iPhone 检查中没能移走卡片；请在返回的截图中确认卡片已消失，而不是依赖工具返回的 `ok`。

## 普通滚动

### 列表

1. 优先使用可见的搜索框，而不是盲目滚动。
2. 探索时使用中等幅度的滑动。
3. 检查返回的截图和 `screen_changed`。
4. 当目标接近视口时，改用较短的滑动。
5. 当屏幕不再变化或到达可见边界时停止。

### 横向轮播

在轮播区域内滑动，而不是跨越全局导航或系统手势区域。继续之前，确认页面或选中项已发生变化。

### 地图和画布

使用短距离平移，重新观察视口，并迭代调整方向。对于这类界面，解读截图比全局图像差异比例更有用。

## 复用稳定参数

当某个控件在多次观察中都被成功操作后，Agent 可以保存一条 procedure 记忆，包含 App、页面、选择器位置、行间距以及有效的交互方式。召回的数值仅作为提示：当前截图的几何信息始终优先。

## 运行边界

- 视觉读取可能会把相似的选择器数值认错；请验证居中的结果。
- 无法获得精确的滚动距离。
- 布局可能因设备尺寸、语言、操作系统版本和 App 版本而变化。
- 手势成功并不代表任务成功；请另行验证结果页面或数值。
